## 状态、优先级与验收门槛

- **已测·真实本地**：实际操作所写本地软件/系统能力，仅限这一层。
- **已测·替身/混合边界/合成数据/控制层/配置契约**：生产代码确实运行，但外部效果被替换；必须保留边界说明。
- **已审·源码**：静态审计，不是运行证明。
- **未测**：从未执行；前置未准备不伪装成失败或通过。执行后才能记PASS/FAIL；确实尝试后因外部缺条件才记BLOCKED。
- **未覆盖**：尚无该负面测试证据/必要测试入口；不能靠其他套件通过顶替。
- **P0**：核心/安全必测。**P1**：异常或条件验证；缺条件保持未测，必须由Review明确批准替代证据或延期，不能自动豁免。

三道门槛分别报告：**S0本地准备 APPROVE**（A21～A25已按各自边界闭合）；**S1真实订阅/联网**（全部未测，先文字）；**S2 iPhone/眼镜**（H01安装已执行、启动待系统信任；其余未测）。当前总体NOT ACCEPTED，PR保持draft。退出安全[#14](https://github.com/andywangyzfh/OpenVision/issues/14)、协调器/身份/失败UI[#15](https://github.com/andywangyzfh/OpenVision/issues/15)已有本地执行及Review；音频性能[#13](https://github.com/andywangyzfh/OpenVision/issues/13)仍待真机测量。P0必须实际满足，P1的替代/延期必须经Review明示。没有“软件测试过所以实际也可以”的推论。

模拟器正常入口不带测试启动参数；`--mvp-ui-testing` 使用fixture。当前生产设计在每次冷启动都不读活动凭据，必须本人点击“恢复本机已有登录”或完成新OAuth后才激活；历史smoke专门关闭恢复的行为不再是正常入口的特殊差异。模拟器能否完成当前ASWebAuthenticationSession＋HTTP loopback组合本身就是O03待验证项，不预先保证，也不要求先连接手机。
